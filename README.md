# Лабораторная работа № 2 — REST API и очередь сообщений

Учебный проект по дисциплине Distributed Systems: два HTTP-сервиса на Flask и асинхронное взаимодействие producer–broker–consumer.

## Цель и реализация

- REST API на порту 5000: получение серверного времени и возврат сообщения.
- Брокер на порту 6000: FIFO-очереди по темам в оперативной памяти.
- Producer отправляет заказы примерно раз в секунду.
- Consumer извлекает заказы и имитирует обработку длительностью 3 секунды.

## Запуск

Требуется Python 3.9+. Из корня проекта создайте виртуальное окружение:

```bash
python -m venv .venv
```

Активируйте его: Windows PowerShell — `.venv\Scripts\Activate.ps1`; Linux/macOS — `source .venv/bin/activate`.

```bash
python -m pip install flask requests
```

В четырёх отдельных терминалах с активированным окружением запустите:

```bash
python api.py
python broker.py
python producer.py
python consumer.py
```

Каждая команда — отдельный процесс. Сначала запустите брокер, затем producer и consumer. Для остановки используйте Ctrl+C.

## API и проверка

| Сервис | Запрос | Результат |
|---|---|---|
| API | `GET /time` | 200, JSON с полем `server_time` |
| API | `POST /echo`, JSON `{"message":"Hello"}` | 200, то же сообщение |
| API | `POST /echo` без `message` | 400 |
| Брокер | `POST /queue/orders`, JSON заказа | 201, заказ добавлен |
| Брокер | `GET /queue/orders` | 200, извлечён первый заказ; 204 при пустой очереди |

Проверить время можно по адресу http://localhost:5000/time. Для проверки накопления очереди остановите consumer, оставив брокер и producer работающими, затем снова запустите consumer.

Сообщения теряются при перезапуске брокера. Извлечение удаляет сообщение без подтверждения обработки и повторной доставки. Проект предназначен для локальных учебных экспериментов.
